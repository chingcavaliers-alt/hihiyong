HIHIYONG v1.3.14.0 Game Data

v1.3.14.0 更新（2026-10-21）
A. 假在線訊號紀錄（只記錄，不改變任何判定）
   - 讀取遊戲的伺服器時間 GLGaeaClient.m_cServerTime。假在線時伺服器不再送資料，預期它會停止更新。
   - 停止超過 60 秒 → Log：SIGNAL_SERVER_TIME_STALL；恢復 → SIGNAL_SERVER_TIME_RESUME（含停止秒數）。
   - 每 30 秒寫一列 Logs\Signals_日期.csv（HP、伺服器時間、活動未變秒數、金幣、背包、假在線狀態）。
   - 「血量監控」卡片新增「伺服器時間：N 秒前更新」。
   - 遇到假在線後，請提供當時的 Log，確認此訊號可靠後再改成正式判定依據。
B. 重啟時不再因 Loading 太久判定失敗
   - 按下「開始遊戲」後改由記憶體判斷角色是否載入（最大 HP > 0），不再只等畫面 HUD 90 秒。
   - 載入完成後切回該視窗執行原本的流程：HUD 確認 → 登入後按鍵 → 位置辨識 → 恢復視窗位置。
   - 超過 10 分鐘只發提醒（Discord + 事件）並繼續等待；超過 30 分鐘才標示「需要人工確認」並保留 game.exe。
   - 載入期間遊戲視窗消失 → 照原本規則 5 秒後自動完整重啟。
C. 排程不再被慢載入卡住
   - 載入 60 秒內完成：佇列等它，行為與舊版相同（登入後按鍵立即送出）。
   - 超過 60 秒仍未載入：佇列先登入下一個帳號，慢的那個在背景繼續等待。
   - 已載入完成的帳號優先處理；登入中與登入後操作共用「前景鎖」，按鍵不會送錯視窗。
   - 執行登入後操作時，視窗切換 / 背包清理 / 視窗配置會暫停（沿用原本的機制）。
設定（HIHIYONG_AutoRecovery.ini 的 [Recovery] 區段，沒有設定就用預設值）：
   AsyncLoading=1                 0 = 關閉，完全使用舊流程
   AsyncLoadingGraceSeconds=60    多久沒載入就先處理下一個帳號
   AsyncLoadingWarnSeconds=600    多久發出「載入過久」提醒
   AsyncLoadingMaxSeconds=1800    多久標示需要人工確認
   沒有 Game.pdb 位置時自動使用舊流程。
其他：resolve_game_offsets.py 新增 ServerTimeOffset 與 ToolVersion；INI 版本較舊時自動重新解析。
驗證：語法檢查通過；背景載入 / 前景鎖 / 訊號紀錄邏輯測試 19 項、記憶體讀取測試 20 項、
      統計測試 17 項全部通過；介面以 Edge 測試通過。自動登入流程尚未在實際遊戲中執行。

HIHIYONG v1.3.13.0 Game Data

基底：v1.3.12.6 HP Auto Recalibration（Recovery / Login / Network Watch / 背包清理 / 視窗切換核心未變更）。

一、主要新功能
1. 遊戲資料改由 Game.pdb 定位（不需要再校正 HP）
   - game.exe 旁的 Game.pdb 記錄了遊戲內部結構。tools\resolve_game_offsets.py 會從中解析
     HP（目前 / 最大）、金幣、經驗值、背包、道具名稱的位置，寫入 HIHIYONG_GameOffsets.ini。
   - 維修更新（game.exe 版本改變）後會在背景自動重新解析，約 2 秒，不需要任何操作。
   - 讀取前會比對遊戲物件的 vftable，確認位置正確才使用；不符時不讀取、不判定死亡。
   - 解析失敗（找不到 Game.pdb 或 Python）時，自動退回 v1.3.12.6 的 offset + 動態校正流程。
   - 需求：已安裝 Python（py.exe）。只用標準函式庫，不需要安裝任何套件。

2. 每日背包統計（左側「📦 背包統計」）
   - 每 5 秒讀取一次各角色的背包與金幣，統計今日新增的道具（含名稱、數量）、金幣增減。
   - 可切換日期查看歷史紀錄，或匯出 CSV（Excel 可直接開啟）。
   - 資料存在 Stats\Inventory_日期.ini；道具名稱快取在 Stats\ItemNames.ini。
   - 重新登入只會重新建立基準，不會把整個背包算成新增。
   - 從倉庫取出、交易收到也會計入新增；存入倉庫計入減少。

二、功能優化
1. 假在線判定：除了 HP，金幣 / 經驗值 / 背包有變化也算角色在活動。
   高回復率模式下 HP 常停在滿血，舊版容易誤判假在線並自動重登。
2. Game.pdb 模式下，登入 / Loading 期間不再改用畫面 HP 判定死亡（避免 HUD 尚未出現被誤判）。
3. 角色登入時若已是死亡狀態（HP 持續 0），不再誤判為「位址失效」。
4. 修正：死亡 30 秒未復活時警報被連續呼叫兩次；補上大括號讓程式碼與實際行為一致
   （本機警報音維持 v1.3.12.0 設計：與 Discord 通知獨立）。
5. 首頁血量欄改為「目前 / 最大」；系統自檢新增「遊戲資料位置（Game.pdb）」項目。
6. 版本號統一由 APP_VERSION 定義（主視窗、網頁、啟動訊息）。
7. 新功能放在 modules\ 下的獨立檔案（GameData.ahk、InventoryStats.ahk），不再加大主程式。
8. 使用 Git 版本管理（見下方），個人設定與執行紀錄不會被納入版本紀錄。

三、本版未處理（風險較高，需另外安排測試）
- 主程式拆分為多個檔案、設定集中管理（目前仍依賴隱藏的舊版介面元件）。
- 計時器互卡的全面重構。
- 首頁改為角色狀態卡、清除未完成的設定頁。

四、驗證
- AutoHotkey 2.0.27 /Validate 語法檢查通過。
- resolve_game_offsets.py 對目前 game.exe（Build 6AD06958-1465000）解析成功，
  HP 位置 game.exe+0xF28440 與 v1.3.12.6 實機動態校正結果一致。
- GameData / InventoryStats 模組測試：以模擬的遊戲記憶體結構驗證 HP、金幣、經驗、背包走訪、
  Big5 道具名稱、未初始化與資料不一致的處理，以及統計存檔 / 讀回 / 排序，全部通過。
- 網頁介面以 Edge 無頭模式載入測試資料，背包統計頁與首頁血量欄顯示正確。
